是一款专为小型医疗机构、中医诊所、理疗康复中心量身定制的高性能桌面管理软件。系统采用 **Tauri 2.0 + Rust + SQLite** 原生后端驱动，结合 **Vue 3 + TypeScript + Element Plus** 现代化前端技术栈，具备启动秒开、极低内存占用、单机脱网可用、数据高度安全等特性。系统覆盖从患者就诊登记、针灸理疗、中医开方，到费用核算、处方打印、门诊日志与统计分析的全业务流程，帮助医护人员提升门诊工作效率。---## ✨ 核心功能特性### 1. 🏥 门诊就诊与病历全流程管理- **散客登记**：支持日常门诊散客快速建档、就诊登记与费用记录。- **针灸理疗病历**：规范化录入主诉、现病史、体格检查、既往史、理疗方案，并支持动态添加/组合理疗项目（如电针、艾灸、拔罐、推拿等）。- **中医中药处方**：  - 智能饮片开方：支持输入克重、单价、付数，自动精确核算总金额；  - 拼音极速检索：集成 pinyin-pro，支持汉字全拼与首字母模糊匹配（如输入 ds 快速联想 党参）；  - 处方模板与历史快速调取。### 2. 📊 门诊日志与多维统计分析- **就诊日志大盘**：按日、按月、按年或自定义时间跨度检索门诊历史记录；- **分类统计图表**：使用 ECharts 可视化展现就诊人次、结算类型构成（现金/省直医保/武汉医保）及就诊类型分布；- **数据报表导出**：支持门诊台账一键导出为标准 Excel (.xlsx) 表格，便于对账及报税。### 3. 🖨️ 统一打印引擎- **处方与病历打印**：内置符合医疗规范的 A4 / A5 处方笺排版样式；- **费用明细清单**：一键生成就诊收费凭证与理疗明细单；- **即时打印预览**：提供 PrintPreviewModal 弹窗预览，支持自定义页边距与不同打印机适配。### 4. 🗄️ 基础数据与机构管理- **中药饮片库**：维护中药名称、单价、功效说明及拼音助记码；- **理疗项目库**：维护康养与治疗服务项目及其定价；- **机构与医师配置**：配置诊所名称、科室设置、执业医师列表及联系方式。### 5. 🛡️ 本地数据安全与容灾备份- **SQLite WAL 高性能存储**：采用预写日志模式（WAL），读写互不阻塞，抗异常断电损坏能力强；- **原生热备份/恢复**：利用 SQLite 官方 Backup API，运行期间即可秒级生成无锁快照备份；- **全量 JSON 导出/导入**：支持跨机器迁移与冷数据归档。---## 🛠️ 系统架构与设计亮点`维康诊所管理系统 (Client Manager) ├── 前端界面层 (Vue 3 + Element Plus + Pinia) │   ├── 业务视图 (散客登记 / 针灸理疗 / 中药处方 / 数据查询 / 门诊日志) │   ├── 共通组件 (处方打印预览 / 拼音快速联想 / 数据详情卡片) │   └── 适配交互层 (Tauri Invoke API 封装) ├── 原生客户端层 (Tauri 2.0 IPC) │   └── 高性能命令调度通道 (Type-safe IPC Command Handlers) └── 本地原生服务层 (Rust + SQLite)     ├── 统一医疗记录核心 (medical_record.rs - 聚合三合一模型与原子事务)     ├── 饮片与项目管理 (chinese_medicine.rs / healing_items.rs)     ├── 版本化迁移引擎 (database.rs - 自动化表结构版本维护)     └── 热备份与管理 (data_management.rs - 原生热备份与无损恢复)`1. **统一数据模型 (Unified Medical Record)**：将散客挂号 (customer)、针灸理疗 (medical)、中药处方 (prescription) 统一收敛为单一主模型，大幅简化了跨业务的综合查询、报表统计与历史回溯。2. **万分位金融级整数精度**：全系统所有金额字段在 Rust 和 SQLite 中统一采用整数存储（1元 = 10,000 单位），彻底杜绝前端与数据库层浮点数精度丢失问题。3. **版本化数据库迁移 (Database Migration Engine)**：内置轻量级版本追踪表 schema_migrations，后续升级版本时无需手动改动本地数据库即可平滑追加表与字段。---## 📂 目录结构`	ext client-manager/ ├── src/ 安装)- **C++ 构建工具**：  - Windows: 安装 Visual Studio 2022 (勾选 “使用 C++ 的桌面开发”)  - macOS: 安装 Xcode Command Line Tools (xcode-select --install)  - Linux: 安装 uild-essential, libwebkit2gtk-4.1-dev 等 Tauri 依赖### 2. 克隆项目与安装依赖`ash# 克隆仓库git clone https://github.com/longpi233/client-manager.git cd client-manager# 安装前端依赖pnpm install `### 3. 本地开发与调试运行以下命令，会自动拉起 Vite 前端开发服务器并编译启动 Tauri 桌面窗口： `ash cargo tauri dev `> **提示**：若仅需单独调试前端界面，亦可直接执行 pnpm dev（在浏览器中访问 http://localhost:3006，部分依赖原生 SQLite 的接口需要桌面容器支持）。### 4. 生产构建打包`ash# 编译并生成桌面客户端安装包 (Windows: .msi/.exe; macOS: .dmg/.app)cargo tauri build ` 编译产物将输出在 src-tauri/target/release/bundle/ 目录下。---## ❓ 常见问题排查 (FAQ)### Q1: 运行 cargo tauri dev 提示 windowClassname was unexpected？- **原因**：Tauri 2.0 CLI 配置校验较 1.x 更加严格，去除了已废弃的非标准窗口属性。- **解决**：确保 src-tauri/tauri.conf.json 中的窗口配置遵循 Tauri 2.0 规范，移除冗余字段。### Q2: pnpm 提示 [ERR_PNPM_IGNORED_BUILDS] 并报错退出？- **原因**：pnpm 11+ 对依赖中包含的构建脚本（如 sbuild、@parcel/watcher 等）默认开启了拦截保护。- **解决**：在项目根目录的 pnpm-workspace.yaml 中配置 llowBuilds 为 rue 即可授权执行。### Q3: 本地提示 husky: Permission denied 无法执行？- **原因**：部分环境限制了对 .git/config 的写锁权限。- **解决**：package.json 中的 "prepare" 脚本已预置 "husky || true" 容错处理，不影响项目的正常安装与编译。---## 📄 开源许可本项目遵循 [MIT License](./LICENSE) 开源协议。欢迎提交 Issue 与 Pull Request 共同改进！
